# 회사 터뜨리기 💥

> 오늘도 고생한 당신에게, 회사 하나 터뜨릴 권리를 드립니다.

**15초짜리 3D 직장인 스트레스 해소 웹게임.** 닉네임을 넣고, 부수고, 랭킹에 오른다.
가상의 사무실에서 야근·회의·수정 요청을 부수고, 마지막에는 거대한 퇴사빔으로 건물을 종이 조각처럼 날린다.

**현재 상태: 플레이 가능. https://sub.uxo.kr/boomcompany 에 배포 중.**
Vite + TypeScript + Three.js 클라이언트와 의존성 없는 Node 서버(정적 파일 + 글로벌 랭킹 API)를 하나의 Docker 이미지로 묶어 Coolify에 배포한다.

기획과 달라진 점: 첫 화면은 **닉네임 입력 → 시작**으로 단순화했고, 결과는 서버 랭킹(상위 10명)에 올라간다. 생일 모드·별명 카드·케이크는 타격감에 집중하기 위해 제거했다. 피날레는 옥상부터 기단까지 건물의 모든 부품이 실제 크기·색 그대로 조각나 날아간다. 아래 기획 본문은 최초 설계 기록으로 남겨 둔다.

```bash
npm ci                                  # 의존성 설치
npm start                               # 랭킹 API + dist 서빙 (PORT=8787 DATA_DIR=.data 로 로컬 실행 권장)
npm run dev                             # 개발 서버 http://localhost:5173/boomcompany/ (API는 8787로 프록시)
npm test                                # 점수·콤보·분노·종료 규칙 + 랭킹 검증 로직 테스트
npm run build                           # tsc 검사 → dist 빌드 → 오프라인 서비스 워커 생성
node scripts/make-icons.mjs             # PWA 아이콘·소셜 미리보기 PNG 재생성 (Playwright Chromium 필요)
```

| 경로 | 역할 |
| --- | --- |
| `src/game.ts` | 렌더러 없는 순수 게임 규칙 |
| `src/scene.ts` | Three.js 사무실, 부품 단위 파괴, 흔들림·히트스톱·섬광·충격파, 퇴사빔 붕괴 |
| `src/audio.ts` | Web Audio 합성 효과음 (노이즈+저음 레이어, 콤보에 따라 피치 상승) |
| `src/main.ts` | 첫 화면, HUD, 입력, 랭킹 표시·등록, 결과 카드 PNG, 공유 |
| `src/pwa.ts` | 설치 안내, 서비스 워커 등록, localStorage 래퍼 |
| `server/index.mjs` | 정적 파일 + `/boomcompany/api/scores` (GET 상위 10, POST 등록). 점수는 `/data/scores.json` |
| `server/scores.mjs` | 이름 정제, 점수 검증, 정렬·순위 계산 (테스트 대상) |
| `tests/` | 게임 규칙과 랭킹 규칙 검증 |

배포: `Dockerfile` 한 개(빌드 스테이지 → node:22-alpine 런타임, 포트 80). Coolify 앱 FQDN은 `http://sub.uxo.kr/boomcompany`, 영구 볼륨 `/data`. 서버는 프록시가 `/boomcompany` 접두사를 벗기든 그대로 넘기든 모두 처리한다.

## 1. 기획의 중심

| 항목 | 결정 |
| --- | --- |
| 이름 | 회사 터뜨리기 |
| 한 줄 소개 | 출근은 했지만, 건물은 못 지켰습니다. |
| 장르 | 3D 디오라마 파괴 액션 + 시네마틱 피날레 + 결과 카드 |
| 대상 | 친구에게 웃긴 생일 선물을 보내고 싶은 사람, 잠깐 스트레스를 풀고 싶은 직장인 |
| 플랫폼 | 모바일 웹 우선, PC 마우스·키보드 지원 |
| 플레이 길이 | 닉네임 입력 → 게임 15초 → 피날레 약 4초 → 결과·랭킹 |
| 핵심 감정 | 귀찮음 → 타격감 → 과장된 해방감 → 친구에게 공유하고 싶은 웃음 |
| 첫 버전 운영 | 로그인·결제·서버 저장 없이 무료 플레이 |

**성공 기준은 첫 화면에서 갖고 싶은 장난감처럼 보이고, 첫 타격부터 손맛이 있으며, 마지막 폭발을 다시 보고 싶은가다.**

모든 장소와 회사는 허구다. 화면의 파괴 대상은 사무용품과 건물이며, 사람 캐릭터는 등장하지 않는다. 로켓 펀치와 광선 등 만화적 연출을 사용한다.

## 2. 첫 방문 경험

1. 선물 상자와 함께 “생일 선물로 회사를 준비했어요.”가 나타난다.
2. 상자가 열리면 작은 사무실 건물이 튀어나온다. 간판은 기본값 **주식회사 내일부터**.
3. “마음껏 터뜨리세요.” 아래 **[선물 뜯고 시작]**을 누른다.
4. 첫 표적 ‘월요일 회의’를 탭하며 바로 게임을 배운다. 첫 타격 후 45초 타이머가 시작된다.
5. 서류 더미, 프린터, 회의실을 부술수록 분노 게이지와 점수가 오른다.
6. 게이지가 차면 **[퇴사빔 발사]** 버튼이 켜진다. 누르거나 시간이 끝나면 피날레로 넘어간다.
7. 생일 축하 폭죽과 결과 카드가 나타난다. **[한 번 더]**, **[카드 저장]**, **[링크 공유]**를 제공한다.

일반 모드에서는 첫 문구를 “오늘 받은 스트레스, 여기 두고 가세요.”로 바꾼다. 생일 모드는 기본 선택하되 준비 화면에서 바꿀 수 있다.

## 3. 게임 규칙 (적용 중인 v2)

> 첫 구상(45초, 피날레 전용 퇴사빔)은 "게이지가 차면 안 쏘고 버티는 게 최선"이 되어 버튼이 무의미했다. v2는 **15초 안에 최대한 부수고, 퇴사빔은 게임 중에 쏘는 폭발 카드**로 바꿨다. 아래가 `src/game.ts`에 구현된 규칙이며 `tests/game.test.ts`가 검증한다.

### 시간과 표적

| 항목 | 규칙 |
| --- | --- |
| 라운드 | **15초**. 첫 유효 타격부터 흐르며, 종료 시 남은 분노 × 20점 보너스 후 건물 붕괴 피날레(약 4초)로 넘어간다. |
| 조작 | 탭·클릭 1회 = 피해 1. 누르고 있기·드래그 자동 공격 없음. 빈 곳 탭은 벌점 없음. |
| 슬롯 | 3층 × 2개 = 6슬롯. 파괴 후 0.35초 뒤 같은 슬롯에 다음 종류가 나온다(회의 자료 → 프린터 → 책상 순환). |
| 마지막 5초 | 타이머가 붉게 바뀐다. |

| 표적 | 타격 | 기본 점수 | 파괴 문구 |
| --- | ---: | ---: | --- |
| 월요일 회의 | 1 | 100 | 이 회의는 메일로 끝났습니다. |
| 무한 수정 프린터 | 2 | 250 | 최종_진짜최종_폭발.pdf |
| 야근 책상 | 3 | 450 | 오늘은 정시 퇴근입니다. |
| **긴급 수정 요청** (황금) | 2 | **800** | 마감 전에 마감을 없앴습니다. |

### 콤보·배율

- 마지막 유효 타격에서 **1.2초** 안에 다시 맞히면 콤보가 이어진다. 콤보 숫자 아래 바가 남은 시간을 보여준다.
- 배율: 콤보 1–4 **×1**, 5–9 **×1.5**, 10–19 **×2**, **20 이상 ×3**. 파괴를 일으킨 타격의 콤보로 계산한다.

### 분노와 퇴사빔 (게임 중)

- 분노: 타격 **+3**, 파괴 **+5**, 최대 100. 보통 속도로 7~8초면 찬다.
- **분노 100 → 퇴사빔 발사**: 화면의 살아 있는 표적을 **전부 즉시 파괴**하고(각 기본 점수 × 현재 배율) **+1,000** 보너스. 분노는 0으로, 콤보는 유지, 표적은 0.5초 뒤 재등장. **게임은 계속된다.**
- 전략: 콤보가 10 이상이거나 책상·황금 표적이 많이 떠 있을 때 쏘면 이득이 커진다. 빠르면 한 판에 두 번 쏠 수 있다.
- 시간 종료 시 퇴사빔을 한 번이라도 쐈거나 분노가 100이면 건물 전체(옥상 → 3층 → 2층 → 1층 → 기단)가 조각나 날아간다. 한 번도 못 쐈으면 분노에 비례해 일부만 무너진다.

### 긴급 수정 요청 (황금 표적)

- 누적 파괴 수가 **7의 배수**가 될 때마다 다음 재등장 슬롯에 황금 표적이 나온다(퇴사빔으로 부순 것도 센다).
- **4초** 안에 못 부수면 사라지고 슬롯은 원래 순환으로 돌아간다. 화면에는 남은 시간이 표시된다.

### 점수 계산 예

회의 자료 2개와 프린터 1개를 4번의 타격으로 부순 뒤 방치하면: 점수 `200 + 250 = 450`, 분노 `4 × 3 + 3 × 5 = 27`. 종료 보너스 `27 × 20 = 540`으로 총 **990점**.

### 결과와 재도전

결과에는 총점, 부순 표적 수, 최대 콤보, 퇴사빔 횟수, 최고 기록 갱신 여부와 **서버 랭킹 순위**를 표시한다. 등급은 총점으로 결정한다.

| 총점 | 칭호 |
| --- | --- |
| 0~4,999 | 오늘도 참은 사람 |
| 5,000~11,999 | 회의실의 재앙 |
| 12,000~21,999 | 정시 퇴근 수호자 |
| 22,000 이상 | 전설의 퇴사자 |

등급 경계는 보통 속도(초당 3탭) 약 9,000점, 빠른 속도(초당 6탭) 약 25,000점을 기준으로 잡았다. 실제 랭킹 분포를 보고 조정한다.

## 4. 화면 구성과 문구

| 화면 | 구성 | 대표 문구 / 행동 |
| --- | --- | --- |
| 준비 | 선물 상자, 제목, 생일 모드, 선택 입력, 시작 버튼 | “생일 축하해. 오늘 회사는 내가 쏜다.” |
| 플레이 | 상단 남은 시간·점수, 중앙 사무실 표적 6개, 하단 분노·퇴사빔 | “회의 하나쯤은 없어져도 괜찮잖아.” |
| 피날레 | 빔 충전 → 발사 → 건물 붕괴 → 케이크 | “업무 종료. 생일 시작.” |
| 결과 | 칭호, 점수, 통계, 저장·공유·재시작 | “건물은 사라졌고, 당신의 생일은 남았습니다.” |

준비 화면에서 **받는 사람 별명(최대 12자)**과 **가상 회사 간판(최대 16자)**을 선택 입력한다. 빈 값은 ‘오늘의 주인공’과 ‘주식회사 내일부터’로 대체한다. 입력값은 HTML로 해석하지 않고 텍스트로만 출력한다.

생일 모드를 켜면 케이크와 축하 문구가, 끄면 퇴근 도장과 “오늘도 수고했어요.”가 나온다. 입력 때문에 바로 시작하는 흐름이 막히지 않도록 선택 입력은 접힌 상태로 둔다.

## 5. 아트 디렉션: 작은 회사, 거대한 해방감

### 첫 화면의 인상

어두운 보랏빛 스튜디오 중앙에 따뜻한 창문이 켜진 **수집용 미니어처 사무실**이 떠 있다. 왼쪽 위의 크림색 조명과 뒤쪽 라일락 조명이 건물 모서리를 감싼다. 바닥에는 부드러운 그림자와 옅은 원형 받침대가 있어 실제 전시물처럼 보인다.

상단 제목은 굵고 큰 한글로, 설명은 짧게 둔다. 화면의 약 65%를 건물이 차지하고, 시작 버튼은 하단에서 한 번에 보인다. 대기 중에는 간판과 책상 소품이 아주 조금 움직이고, 화면 진입 때 건물이 아래에서 올라오며 자리 잡는다.

| 요소 | 시각 방향 | 구현 포인트 |
| --- | --- | --- |
| 건물 | 둥근 모서리, 두툼한 슬래브, 전면이 열린 3층 사무실 | 층·벽·가구를 분리한 모듈식 3D 모델 |
| 1층 | 복사실: 프린터, 종이 더미, 택배 상자 | 종이 파편과 프린터 상태등 |
| 2층 | 야근 사무실: 책상, 모니터, 커피, 화분 | 모니터 발광, 책상 반동, 컵 흔들림 |
| 3층 | 회의실: 긴 테이블, 보드, 벽시계 | 보드 균열, 메모지 흩날림, 시계 기울어짐 |
| 재질 | 무광 플라스틱, 도장한 금속, 반투명 창문, 종이 | 거칠기·색·발광 차이로 분리, 투명 재질 면적 제한 |
| 배경 | 자주색 안개와 흐릿한 도시 실루엣 | 저비용 배경 레이어, 주인공보다 낮은 대비 |
| HUD | 크림색 큰 숫자, 콤보 타이포, 분노 계기판 | 선명한 HTML UI, 화면 가장자리 여백 확보 |
| 필살기 버튼 | 충전량이 흐르는 두꺼운 보라색 버튼 | 완료 시 테두리 빛과 한 번의 팽창 모션 |

표적 슬롯의 게임 규칙은 모든 층에서 동일하다. 층별 가구와 색은 배경 정체성을 만들며, 교체되는 표적 3종의 실루엣과 HP 표시는 일관되게 유지한다.

**팔레트:** 배경 `#171827`, 사무실 `#FFF4DB`, 보라 `#7048FF`, 라일락 `#B8A4FF`, 타격 노랑 `#FFD84D`, 과열 코랄 `#FF665A`. 배경은 어둡게, 건물은 따뜻하게, 타격 순간만 강한 색을 사용한다.

### 한 번의 타격에 담을 반응

| 시간 | 화면 | 소리·입력 피드백 |
| --- | --- | --- |
| 0–80ms | 타격점의 작은 별 모양 섬광, 표적 눌림과 반동 | 짧은 타격음, 지원 기기에서 선택적 짧은 진동 |
| 80–220ms | 금이 퍼지고 가까운 소품이 뒤늦게 흔들림 | 종이·플라스틱·금속에 맞는 잔향 |
| 파괴 후 0–350ms | 3D 파편이 바깥으로 튀며 표적 자리 정리 | 파괴음, 점수 숫자의 탄성 있는 등장 |
| 350–900ms | 종이는 천천히 회전하며 낙하, 무거운 조각은 빠르게 떨어짐 | 연타 시 효과음 동시 재생 수와 음량 제한 |

주변 파편은 남아 있어도 다음 표적의 클릭 판정을 가리지 않는다. 큰 조각은 짧게, 작은 종이는 길게 남겨 무게 차이를 만든다. 건물 외벽에는 누적 파괴량에 따라 균열·기울어진 간판·꺼진 창문이 남아 한 판의 진행이 눈에 보이게 한다. 이 흔적은 장식이며 표적 HP나 점수에 영향을 주지 않는다.

### 4초 퇴사빔 연출

| 구간 | 연출 |
| --- | --- |
| 0.00–0.60초 | HUD가 옅어지고 카메라가 건물에 다가온다. 먼지와 종이 조각이 중심으로 모인다. 주변 소리는 작아진다. |
| 0.60–0.90초 | 간판과 창문이 보라색으로 차오른다. 짧은 정적 뒤 빔이 점화된다. |
| 0.90–1.40초 | 광선이 건물을 관통하고 원형 충격파가 퍼진다. 약 0.12초 동안 파편 움직임을 느리게 해 충돌 순간을 강조한다. |
| 1.40–2.70초 | 층별로 0.12초 간격을 두고 외벽과 가구가 분리된다. 카메라가 뒤로 빠지며 종이·컨페티가 화면을 채운다. |
| 2.70–4.00초 | 먼지가 걷히면 받침대 위에 케이크가 남는다. 촛불과 생일 문구가 켜지고 결과 카드가 올라온다. |

분노 미달은 같은 타임라인에서 빔 두께·분리되는 조각 수·카메라 이동량을 줄인다. 일반 모드는 케이크를 퇴근 도장으로 교체한다. 움직임 줄이기에서는 고정 카메라, 화면 흔들림·슬로모션 제거, 적은 파편과 부드러운 전환을 사용한다.

### 사운드와 접근성

- 배경음은 짧은 루프로 구성하고 분노가 차면 타악기와 저음을 더한다. 필살기 직전에는 음량을 낮추고 발사 순간을 강조한다.
- 종이 찢김, 프린터 오류음 패러디, 빔 충전음, 축하 팡파르에 각기 다른 음색을 쓴다. 첫 사용자 조작 후 오디오를 활성화한다.
- 음소거·움직임 줄이기 설정, 색 외의 HP 표시, 최소 44px 탭 영역, 키보드 표적 선택을 제공한다. 고속 섬광을 반복하지 않는다.
- 초기 모델은 직접 만든 기본 도형·모듈형 메시를 조합한다. 질감과 효과음은 직접 만들거나 사용 권한이 확인된 소재를 사용한다.

## 6. 공유 경험

**결과 카드 예시**

> 오늘의 주인공님, 생일 축하합니다! 🎂  
> 오늘의 업적: 주식회사 내일부터 철거 완료  
> 8,450점 · 정시 퇴근 수호자  
> 회사 터뜨리기

- **카드 저장:** 현재 별명·가상 간판·점수·칭호를 담은 PNG를 기기에서 생성한다. 이미지 생성 실패 시 결과 텍스트 복사로 이어진다.
- **링크 공유:** Web Share API가 가능하면 공유 창을 열고, 미지원이면 링크를 복사한다. 복사도 실패하면 직접 선택 가능한 링크를 보여준다.
- **개인화 범위:** 첫 버전은 기본 게임 주소만 공유한다. 별명과 간판은 URL에 넣지 않으며, 결과 카드에만 포함한다.
- 공유 취소는 오류 팝업 없이 결과 화면으로 돌아온다. 업로드나 공개 피드는 만들지 않는다.

## 8. 구현 설계

아래는 구현 시 사용할 제안이며, 아직 설치하거나 검증한 기술 구성은 아니다.

| 영역 | 제안 | 이유 |
| --- | --- | --- |
| 앱 | Vite + TypeScript | 서버 데이터가 없는 작은 게임을 정적 파일로 빌드 |
| 3D 엔진 | Three.js + WebGL 렌더러 | 모듈형 건물, 조명, 카메라, 인스턴스 파편을 한 장면에서 처리 |
| 화면 | HTML/CSS HUD + WebGL Canvas | 선명하고 접근 가능한 UI와 풍부한 3D 장면을 함께 구성 |
| 입력 | Pointer Events + Raycaster, HTML 표적 버튼 | 화면 좌표를 3D 표적으로 변환하고 키보드도 같은 공격 함수 사용 |
| 셰이더 | 균열 마스크·발광 펄스·노이즈 디졸브·충격파 | 명중, 과열, 붕괴를 재질과 빛의 변화로 표현 |
| 후처리 | 제한된 Bloom, 톤 매핑, 품질별 해상도 | 빔과 간판을 빛나게 하고 UI는 후처리 밖에 유지 |
| 파괴 | 사전 분할 메시 + 파편 풀 + 단순 탄도 운동 | 조각별 무게감과 층별 붕괴를 예측 가능하게 제어 |
| 렌더링 | requestAnimationFrame + 고정 간격 파편 업데이트 | 게임 시간, 장식 물리, 시네마틱 재생 속도를 분리 |
| 효과음 | Web Audio 또는 로컬 오디오 파일 | 첫 조작 이후 재생, 음소거 일괄 적용 |
| 결과 카드 | 피날레의 3D 프레임 + 별도 Canvas 2D 합성 | 실제 플레이 장면을 담은 1080 × 1350px 결과 PNG 생성 |
| 저장 | localStorage | 최고 기록과 음소거·동작 설정만 저장 |
| 배포 | Coolify에서 정적 빌드 제공 | 기존 운영 환경을 활용하는 후속 배포 계획 |

### 모듈과 데이터 흐름

```text
Pointer / Keyboard
        ↓
InputController → GameSession → 점수·콤보·분노·상태
                        ↓ 도메인 이벤트
                 SceneDirector
                 ↙     ↓      ↘
          Building  VFX/Camera  Audio
                        ↓
                 ResultComposer
```

- `GameSession`은 렌더러 없는 순수 TypeScript로 관리한다. 파괴 이벤트에 표적 ID·세대 번호·점수 변화를 포함하여 재등장한 표적과 이전 효과를 구분한다.
- `SceneDirector`는 `hit`, `destroy`, `rage-ready`, `finale` 이벤트로 연출한다. 시각적 슬로모션이 점수·콤보 시계를 바꾸지 않도록 한다.
- `Building`은 층·외벽·표적·장식·파편 원형을 분리한다. 충돌 검사는 표적용 단순 메시 6개만 대상으로 한다.
- `QualityManager`는 프레임 시간을 측정해 해상도·파편·후처리를 조절한다. 공격 판정·점수·타이머는 품질 등급과 무관하다.
- `AssetManager`는 공용 geometry/material과 오디오를 재사용한다. 재시작 때 객체 풀을 초기화하고 앱 종료 때 GPU 자원을 해제한다.

같은 모양·재질의 파편은 `InstancedMesh`로 묶어 그리기 호출을 줄인다. 입력은 `Raycaster`로 표적 전용 레이어만 검사하고 가장 가까운 유효 표적 하나를 고른다. 발광 연출에는 `UnrealBloomPass`의 밝기 임계값을 조절한다. 관련 기능은 [Three.js InstancedMesh](https://threejs.org/docs/pages/InstancedMesh.html), [Raycaster](https://threejs.org/docs/pages/Raycaster.html), [UnrealBloomPass](https://threejs.org/docs/pages/UnrealBloomPass.html) 공식 문서를 기준으로 구현한다.

### 파괴와 렌더링의 구체적인 선택

1. **사전 분할:** 책상·프린터·외벽은 온전한 메시와 부서진 조각 묶음을 준비하고 파괴 시 전환한다. 실시간 메시 절단을 실행하지 않는다.
2. **장식 물리:** 큰 조각은 중력·회전·바닥 한 번 튕김, 종이는 공기 저항·좌우 흔들림을 적용한다. 파편끼리 충돌하지 않으며 점수에 관여하지 않는다.
3. **작은 효과:** 먼지와 섬광은 인스턴스 평면 또는 Points로 처리한다. 반투명 레이어가 전체 화면에 겹치는 양을 제한한다.
4. **조명:** 기본광·주광·테두리광을 사용하고 실시간 그림자는 주광 하나에 집중한다. 낮은 품질에서는 바닥 그림자를 평면 텍스처로 대체한다.
5. **파편 시간:** 고정 1/60초 간격으로 업데이트하고 프레임당 최대 4회 보정한다. 초과 누적분은 장식 시뮬레이션에서 버리되 게임 타이머는 실제 활성 경과시간을 유지한다.
6. **입력 접근성:** 3D 표적 위치를 화면 좌표로 투영해 키보드 포커스 테두리를 표시한다. 버튼과 Canvas 입력은 한 경로로 처리하여 중복 공격을 막는다.
7. **결과 캡처:** 피날레의 정해진 순간에 렌더 타깃으로 한 번 캡처한다. 캡처 실패 시 준비된 일러스트와 결과 수치로 카드를 생성한다.

### 모바일 성능 예산

아래 수치는 구현 전 목표다. 실제 기기 측정으로 조정하며, 최고 품질의 모든 효과를 모든 기기에 강제하지 않는다.

| 항목 | 기본 모바일 | 고품질 PC |
| --- | --- | --- |
| 목표 프레임 | 60fps, 저사양 품질에서 안정적인 30fps | 60fps |
| 렌더 픽셀 비율 상한 | 1.5, 저사양 1.0 | 2.0 |
| 동시에 살아 있는 3D 파편 | 최대 180개, 저사양 60개 | 최대 500개 |
| 먼지·컨페티 인스턴스 | 최대 300개, 저사양 100개 | 최대 1,000개 |
| 메인 장면 draw call | 100회 이하 목표 | 150회 이하 목표 |
| 그림자·Bloom | 그림자 1개와 저해상도 Bloom, 저사양에서는 대체·비활성화 | 그림자 1개와 Bloom |
| 첫 플레이 필수 자산 | 압축 전송량 합계 5MB 이하 목표, 추가 음원은 지연 로드 | 같은 자산 우선 사용 |

연속 3초 평균 프레임 시간이 22ms를 넘으면 효과 품질을 한 단계 낮추고, 한 판 중에는 다시 올리지 않아 품질 진동을 피한다. 낮은 품질에서도 33ms를 지속적으로 넘으면 렌더 해상도를 추가로 낮추고 기기별 병목을 조사한다. 측정에는 후처리를 포함한 전체 프레임 시간과 95백분위 값을 함께 기록한다.

WebGL 초기화 실패는 정적 안내와 재시도 경로를 제공한다. 컨텍스트를 잃으면 즉시 일시정지하고 복구 후 장면을 재구성한다. 복구 불가 시 재시작을 안내하며, 이를 정상 플레이 성공으로 집계하지 않는다.

게임 상태는 `ready → playing ↔ paused → finale → result`로 관리한다. 재시작은 `result → ready`로 돌아가며, 표적·점수·게이지·이전 이벤트 핸들러를 초기화한다.

- 타이머는 첫 유효 명중부터 시작한다. 애니메이션 프레임 수로 시간을 세지 않는다.
- 탭 전환·화면 잠금 감지 시 일시정지하며, 복귀 후 **[계속하기]**를 눌러야 다시 진행한다. 피날레 중 숨겨진 경우도 연출 시간을 보존한다.
- 저장소 접근이 차단되어도 메모리 상태로 플레이하고 결과 화면까지 진행한다.
- 별명과 간판은 페이지 세션 메모리에만 보관한다. 분석·서버 전송은 첫 버전에 없다.
- 필수 자산 로드와 셰이더 준비를 마친 뒤 시작 버튼을 활성화한다. 추가 음원 실패는 무음으로 진행하며, 필수 장면 실패는 재시도 안내로 연결한다.
- Coolify 연동은 구현 후 진행한다. 빌드 명령은 `npm ci && npm run build`, 산출물은 `dist`를 기준으로 계획하고 실제 실행 구성을 배포 전에 검증한다.
- 운영 키와 인증 정보는 소스·문서·이미지·Git 기록에 넣지 않는다. 필요한 운영 설정은 배포 환경에서 관리한다.

| 1. 한 방의 완성 | 3D 사무실 한 층, 표적 한 개, 조명·파편·타격음 | 모바일에서 타격 전후가 명확하고 성능 예산을 만족한다. |
| 2. 한 판의 완성 | 3층 건물, 표적 6개, 타이머·콤보·분노·점수 | 처음부터 결과까지 규칙이 연결되고 재시작할 수 있다. |
| 3. 대표 장면 완성 | 셰이더, 누적 파괴, 카메라, 4초 퇴사빔, 사운드 믹스 | 충전→충돌→붕괴→케이크의 흐름과 최고 부하 성능을 검증한다. |
| 4. 선물 포장 | 생일 모드, 입력, 실제 장면 결과 카드, 공유 | 별명이 반영된 고해상도 이미지를 저장할 수 있다. |
| 5. 출시 점검 | 품질 자동 조절, 접근성·오류 검증, Coolify 배포 | 모바일과 PC에서 실제 URL로 전체 흐름을 완료한다. |

배포는 실제 게임 구현과 아래 검증을 마친 뒤 진행한다. 현재 공개 저장소를 만드는 작업만으로 서비스가 배포되는 것은 아니다.

### 반드시 확인할 시나리오

1. 입력값 없이 바로 시작해 첫 타격부터 45초가 흐르고 정상 종료되는가?
2. 한 번도 공격하지 않으면 시작 전 상태를 유지하고, 첫 공격 후 방치하면 낮은 점수로 끝나는가?
3. 콤보 4→5, 9→10 경계와 1.2초 초과 초기화에서 점수가 규칙과 일치하는가?
4. 분노 100의 수동 발사·자동 발사, 분노 미달 종료가 각각 한 번만 실행되는가?
5. 파괴 중인 표적 연타, 멀티터치, 필살기 연속 클릭으로 점수가 중복되지 않는가?
6. 일시정지·탭 전환·복귀와 10회 재시작에서 타이머나 효과음이 겹치지 않는가?
7. 긴 한글·이모지·HTML 형태 입력도 화면을 깨뜨리지 않고 텍스트로 표시되는가?
8. iOS Safari·Android Chrome·데스크톱 Chrome에서 표적 터치, 카드 저장, 공유 또는 대체 동작이 가능한가?
9. 360px 너비 화면, 키보드 조작, 음소거, 움직임 줄이기에서 진행을 막는 요소가 없는가?
10. 배포 URL에서 새로고침·정적 자산 로딩이 정상이며 브라우저와 서버 로그에 관련 오류가 없는가?
11. 피날레 최대 파편 상태에서 프레임 시간·그리기 호출·메모리를 측정했고 품질 하향이 실제로 동작하는가?
12. GPU 컨텍스트 손실·복구, 자산 로드 실패, 화면 회전에도 재시도 또는 정상 진행 경로가 있는가?
13. 10회 재시작 후 GPU geometry·texture 수와 이벤트 구독 수가 계속 늘어나지 않는가?
14. 준비·일반 타격·분노 100·빔 충돌·결과의 다섯 장면을 캡처해 구도·텍스트·빛 번짐을 확인했는가?

점수·콤보·종료 중복 방지는 로직 테스트로 확인하고, 타격감·공유·모바일 입력은 실제 브라우저 플레이로 확인한다.

## 10. 출시 후 판단

첫 사용성 테스트에서 다음 질문을 확인한다. 수치는 성과가 아니라 초기 검증 목표다.

- 별도 설명 없이 5초 안에 첫 공격을 하는가?
- 첫 플레이에서 분노 100에 도달하고 필살기의 존재를 알아차리는가?
- 45초가 길게 느껴지지 않으며, 다시 하기 버튼을 자연스럽게 찾는가?
- 결과 카드가 생일 축하 선물로 보이며 문구가 웃긴가?
- 파괴 반응이 약하다면 콘텐츠를 늘리기 전에 타격 애니메이션과 사운드를 먼저 개선한다.

**개발 우선순위: 매력적인 3D 한 장면과 첫 타격 → 완성도 높은 퇴사빔 → 생일 결과 카드 → 추가 콘텐츠.**
